# R127 — The ORIGINAL build-mode terrain tool items (the Terrain subcategory cells)

Round protocol: Hermes scouts (2 background) → decode/pin → port → gate → this
evidence. Gate check `uibldt` (74-check set). Canon dump:
`r127-terraintools-canon.txt` (generated by `make_r127_terraintools_canon.py`).

## Why this round (scout findings)

The terrain tool cells were the port's actively-BROKEN catalog surface: the FSO
`UICatalogTerrainResProvider` resolves TSO `UIFileIDs` through the
`uigraphics/*.dat` TSO provider — which mounts nothing on a TS1-only install —
so `UIElement.GetTexture` returned its 1×1 white fallback (blank cells), and
the Grass tool mounted a wrong-asset TSO placeholder
(`buildpanel_wallpaperbtn`). Names were hardcoded English, prices fake (§1).

## What was mounted

- **4 cell plaques** (res_cpanel.RT kBldSbTl*): `TerrainUpIcon` 144×33,
  `TerrainDownIcon` 144×34, `TerrainLevelIcon` 156×33 (cpanel\Build) +
  `TerrainGrassIcon` 144×32 (cpanel\HDBuild, Hot Date).
- **4 popup thumbs** (kBldPopup*): `PopupTerrainUp/Down/Level` + `popupGrass`,
  all 145×103 — mounted as the catalog `GetThumb` art (the description popup
  shows them), matching the FSO provider's own TSO mapping comments
  (icon=plaque, thumb=popup).
- All 8 pin name+len+dims+sha256 in the gate (pins REGENERATED from the FAR
  bytes by `regen_gate_shas.py`, never hand-typed).
- The mapping id 0 raise / 1 level / 2 grass / 3 lower is verified against the
  RT symbol lines recorded verbatim in the dump.

## The raise/lower split (original structure restored)

The original has SEPARATE Up/Down tools — distinct icons AND distinct popups
per direction (kBldSbTl/kBldPopup pairs). The port had merged them into one
"Raise/Lower Terrain" tool. R127 splits them back:

- **FreeSO submodule** (`UITerrainRaiser.cs`, commit 0c1b1ebf): the ctor now
  honors its previously-ignored `parameters` arg — `parameters[0]==1` = lower
  mode (drag deltas invert in MouseUp and Update; the down cursor graphic
  shows). TSO callers pass an empty list, so TSO behavior is unchanged.
- **Client**: `UIOriginalTerrainResProvider` (Simitone.Client…Catalog)
  replaces the TSO-ID provider for all four items; `AddTerrainTools` builds 4
  items in RT popup order — Up(3600), Down(3601), Level(3602), Hot Date
  Grass(3607) — Raise/Lower as `UITerrainRaiser` (lower carries
  `Parameters={1}`), Flatten as `UITerrainFlatten`, Grass as `UIGrassPaint`.
- `UICatalogItem`: build-tool plaques render at NATURAL size centered in the
  cell (provider-typed via `NaturalIcon`, not an aspect heuristic — a 41px-fit
  would crush a 144×33 plaque to 41×9), with the fake §1 price label hidden
  (the original plaques carry no price text; terrain cost is engine-charged on
  use).

## Negative space / disclosed residuals

- **No original tool-NAME strings exist**: the r127 UIText.iff scan over every
  STR# English entry found only 'Terrain Tool' (STR# 139 [0], the page name),
  optionstrs' Terrain Detail entries, and Help-table lore — no per-tool name
  table (TSO used f107, absent here). The RLE8 ASCII reads prove the
  plaques/popups are PICTORIAL (arrows / level grid / grass blades — no baked
  text). Names stay port-authored: Raise/Lower/Flatten Terrain, Grass Tool.
- `GetDescription` returns null — the original instructions live in the popup
  art (the RLE8 reads are archived).
- Corpus-documented for future rounds (NOT gate-pinned): the roof family —
  `roofpatterntemplate` 180×45 = 4×45 four-frame sheet (the original roof
  cell composes a swatch inside it), `popuproofpattern`/`popuproofpitch`,
  `roofflat/shallow/medium/steep` (the pitch buttons; the port has no pitch
  UI) — plus Hand/Pool/Water icons and popups.
