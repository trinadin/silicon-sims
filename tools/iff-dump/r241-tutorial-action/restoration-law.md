# R241 tutorial “show situation info” action

This is an engine action restoration under the approved original UI restoration. It changes no geometry. Maintained source is the Simitone fork and its maintained FreeSO submodule; no original data, upstream mirror, package or generated binary was modified here.

## Independently recovered contract

Run `python3 tools/iff-dump/r241-tutorial-action/recover.py` against the owner's local original executable and Objects.far. It verifies executable SHA256 `33c76da298841dcaf8402eff8814700bb20e36bb22878d00ea16fcc874c06a5f`, reads the unpacked DATA section, follows the actual dispatch table and extracts the actual Tutorial.iff BHAVs. `metadata.json` records the resulting addresses, pinned instructions, resource hash and seven decoded nodes. The adjacent disassemblies can be regenerated with `r145/capdis2.py`; addresses below are executable file offsets, not CODE-relative virtual addresses.

* `ObjectModule::ShowTutorialInfo` e2bf0..e2c30 reads tutorial owner+ac. With an owner it passes the owner's private Behaviors, initial StackObjectID0, name `show situation info` (TOC-5a30 → DATA47dd8 +72), and null arguments to `cXObject::RunTree` efd30.
* `RunTree` resolves the name and calls `TreeSim::RunCheckTree` 153ec0. That pushes a check sentinel and executes a nested check; it preserves the existing main stack. It does not call dialog response or directly paint/reopen a window.
* Original Tutorial GUID c3249a1d, private BHAV4099, executes nodes **0 → 2 → 1**. Node0 assigns **MyAttribute1=1**; node2 assigns **StackObjectID=MyObjectData11 (self ObjectID)**; node1 executes primitive49 and returns true. Scope10 is StackObjectID, not Temp0. Earlier shorthand identifying that scope as a temporary register was corrected before implementation.
* Primitive49 is the entry at DATA48438 +49*4; CODE pointer e77a4 translates to file f0634. It resolves the stack object, throws error21 if absent, then asks `GetMainSimElem`153570 for the active main frame. That function scans to the temporary check sentinel and returns the frame below it; the normal no-check case returns the current stack top.
* At f06b4 the active opcode is masked. **Opcode0** zeroes parameter0 and clears scheduler low16 while preserving high16. **Opcode17** zeroes parameter0 without changing scheduler status. Other opcodes, absent main frame, or absent current node are successful no-ops. This is not an unconditional persistent future interrupt.
* Native `TryIdle` f13c0..f1558 consumes the scheduler wake (low16=0) before decrementing: it zeros the operand-selected parameter, resets scheduler low16 to ffff, and returns true. The parameter remains0 and there is no RNG call. This selected parameter can differ from parameter0, which opcode49 itself zeroed.
* Tutorial BHAV4146 “pause ticks” sleeps at node0. After waking it tests MyAttribute1; when1, it clears the attribute and **returns false**. Its caller can redisplay the current situation. The icon does not skip ahead by answering an outstanding dialog. Calling the action while another node is active merely leaves the redisplay attribute for the original script to observe.

## Implementation and scope

`VMNetTS1TutorialInfoCmd` is command49 in the port's network command namespace (independent of primitive49). Its payload is only the existing uint ActorUID: the full envelope is five bytes. It rejects TSO and missing/dead/threadless tutorial owners, resolves the private named tree and runs it immediately through `EvaluateCheck`. It does not modify the normal thread, current instruction pointer, queue, dialog response, blocking owner, game speed, or selected avatar directly. The native BHAV itself changes the redisplay attribute and notifies the current idle.

`VMNotifyOutOfIdle` now has an original-backed TS1 branch. The existing TSO behavior remains unconditional interrupt/reschedule with success on missing target. In TS1, opcode0 zeroes Args0 and uses the port scheduler/Interrupt machinery to represent the native scheduler wake; opcode17 only zeroes Args0. Other instructions do not receive a future wake flag. A missing TS1 target returns primitive ERROR; the port has no numeric error21 payload here.

`VMSleep` consumes a TS1 Interrupt before decrementing. It zeros the operand-selected argument, clears ScheduleIdleStart/Interrupt and returns true without RNG. This also affects other existing callers that set TS1 Interrupt during sleep: they now finish with parameter0 (or the selected parameter) equal to0, instead of a decremented negative/stale value. TSO keeps its old decrement-before-interrupt behavior. No yielding/control-flow classification changed, so no JIT version change is required.

The port's check execution uses a separate temporary thread rather than the native sentinel on one stack. The named tutorial tree does not touch temporary registers; the owned main frame and its stack-object value remain intact. The native immediate action and later redisplay remain distinct.

## Validation and limits

`AutotestTutorialPresentation.Check(out string diagnostics)` uses a separate unticked VM and original resource definitions, with two inert tutorial objects. It pins original BHAV instruction bytes, invokes the actual named tree, verifies the active frame/args/temps/queue and both dialog states survive, then advances only the original pause4146 check to prove false-return redisplay and flag clearing without RNG. Synthetic independent idle0/17/other/no-frame/missing-target fixtures cover opcode49. Another fixture uses an operand-selected parameter1 to establish the native wake-before-decrement law. TSO fixtures preserve its missing-target/empty-stack/sleep behavior. Command guards and exact five-byte serialization are tested. No owner's live lot, tutorial state or files are used as fixtures.

Metadata recovery passed locally. The root agent owns compilation, runtime results and UI integration; this subtask did not launch or build the game. Root will record integrated results separately.

This does not claim complete idle-engine equivalence: the broader port sleep duration/RNG policy and IdleForInput scheduling predate this change. In particular, primitive49 deliberately does not add a reschedule for opcode17 because the native dispatcher does not. Restoring any broader IdleForInput scheduling behavior requires its own original-backed review. Presentation/reopen timing is driven by the tutorial's existing script; no speculative cached-dialog shortcut was added.

JIT review: both Sleep and Notify use `CSFallbackPrimitive`, so compiled modules call the updated handlers. `NotifyStackObjectOutOfIdle` retains its existing non-yielding `SimanticsTrue` classification. `CSTranslator.OutputBlock` discards such return values, so the new missing-target ERROR is verified through the interpreter/direct handler; compiled propagation of primitive errors remains a broader pre-existing limitation. Changing classification alone would not restore native error propagation. The valid tutorial tree sets a live self target and is unaffected.

Integrated runtime result: root's first R241 packaged focused run passed `uitutorial-action`, including actual named-tree execution, pause redisplay, main stack/dialog preservation, notify/wake fixtures, TSO isolation and registry serialization. The independent PIP opcode checks also passed. A separate new UI fixture lacked a test VM driver and was being corrected by root; it did not invalidate the engine action result. No runtime was launched by this subtask.
