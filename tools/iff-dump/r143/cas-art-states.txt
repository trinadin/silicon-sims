R143 — cas-art-states.txt
Programmatic state-count analysis of every CAS / neighborhood button sheet in
tools/iff-dump/r142/art/ (Res_Nbhd far members, all 8bpp BI_RLE8 unless noted).

METHOD (no eyes; pure pixel statistics, PIL decodes RLE8 BMPs natively)
  1. BMP headers parsed raw (bfSize / BITMAPINFOHEADER compression code).
  2. Each file decoded to RGBA; key color detected (pure-magenta corner test).
  3. Mask = pixel is ink (non-key). Candidate decompositions H k=2..8, V k=2..8,
     grid 2..4 x 2..4, keeping only even-divisions whose every interior boundary
     sits between two >=90%-key columns (magenta seam law).
  4. Disambiguation: per-state mask cross-correlation (all pairs) + ink balance
     (min/max ink) + per-state ink bbox. A true N-state sheet has all cells
     similar AND each cell holding a complete centered glyph; over-subdivision
     shows asymmetric bboxes / low adjacent correlation.
  5. OPAQUE sheets (no magenta key; Done/Cancel/PAF plates) get the same test
     with a column-mean RGB profile correlation instead of the key seam.
  6. ENGINE LAW cross-check against the r143 PPC disasms (cTSWinBtn::SetImage
     = vtable+0x1a4 with cols in r5, rows in r6): cols=4 rows=1 is used by
     cawindesigncharacter-init (2 sites), cawindesignfamily-init, nbhd
     createbutton helper, and the personality-widget button builder; the ONE
     exception found is kPickFamilyItemBkg = SetImage(art, cols=1, rows=3).

KEY COLOR LAW
  Every magenta-keyed sheet has (255,0,255) at bottom-left, top-left AND
  bottom-right corners — pure magenta is the engine key. The port's loader
  already masks this family (ImageLoader.ManualTextureMaskData, R>=248 &&
  B>=248 && G<=4 -> alpha 0, FreeSO/TSOClient/tso.files/ImageLoader.cs:405-419).
  Opaque plates (Done/Cancel/PAF, backgrounds) carry no key — bottom-left is a
  content color.

LEGEND  states layout: H=side-by-side, V=stacked, G=grid. conf: HIGH/MED/LOW.
